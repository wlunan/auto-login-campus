# 方案设计

## 总体思路

不在路由器侧做认证，而是在电脑侧写一个轻量保活脚本：

```
┌─────────────────────────────────────────┐
│  某品牌笔记本 (Windows 11)              │
│                                         │
│  ┌──────────────┐    每1分钟           │
│  │ 任务计划      │ ──→ auto_login.ps1    │
│  │ (SYSTEM)     │                       │
│  └──────────────┘                       │
│         │                               │
│         ▼                               │
│  GET http://1.1.1.1 (不跟随跳转)        │
│         │                               │
│    正常 ─┴─→ 写心跳日志退出              │
│         │                               │
│  被劫持：302 Location，或 200/403 +     │
│          portal 特征 HTML               │
│         ▼                               │
│  提取 portal.do?wlanuserip=...&mac=...  │
│  （提不出参数则主动 GET portal.do 兜底） │
│         │                               │
│         ▼                               │
│  GET /quickauth.do?userid=2023000000@htu│
│                     &passwd=***         │
│                     &wlanuserip=...     │
│                     &wlanacname=...      │
│                     &mac=...&vlan=...    │
│         │                               │
│         ▼                               │
│  JSON code=0 → 成功                      │
│         │                               │
│        失败                             │
│         ▼                               │
│  5秒后重试，最多3次                      │
│                                         │
│  GameViewer Service (LocalSystem Auto)  │
│  网络通 → 自动连接网易服务器 → 可被远程  │
└─────────────────────────────────────────┘
            │
            ▼
    HTU_Student (Open WiFi)
            │
            ▼
    BRAS (HSD-BRAS-2) → 校园网/互联网
```

## 认证流程逆向

从 Portal 页面 JS（common.js + portalUtil.js）逆向得到：

1. 用户输入账号密码后，前端先 POST `http://10.101.2.239:8081/user/check` 校验（可选，失败也会继续提交）
2. 真正认证：GET `http://10.101.2.194:6060/quickauth.do`
3. 参数：
   - `userid` = 账号 + 后缀（如 `2023000000@htu`）
   - `passwd` = 密码
   - `wlanuserip` / `wlanacname` / `mac` / `vlan` / `hostname` / `ssid`：从 302 跳转 URL 中透传
4. 返回 JSON：`{"code":"0","message":"..."}` 表示成功

## 脚本设计要点

### auto_login.ps1

- **配置读取**：`config.ini`，账号密码与逻辑分离
- **网络检测**：HTTP 探测 `http://1.1.1.1`（`AllowAutoRedirect=false`），失败再探 `msftconnecttest.com`；**不用 ping**，因为 BRAS 放行 ICMP 但拦截 HTTP，ping 通不代表已认证。ping 仅作离线时的辅助诊断
- **代理处理**：`[System.Net.WebRequest]::DefaultWebProxy = $null`，确保内网请求直连，不被 Clash Verge 劫持
- **Captive 捕获**：`HttpWebRequest.AllowAutoRedirect = $false`；3xx 看 `Location`，2xx/403 读响应体匹配 portal 特征（深澜存在 200 透明劫持，部分 BRAS 用 403 承载认证页）；参数提取失败时兜底主动 GET `portal.do`
- **重试**：失败后 5 秒重试，最多 3 次
- **日志**：UTF-8 追加写入 `logs/auto_login.log`，在线时 30 分钟写一次心跳避免刷爆
- **权限**：SYSTEM 运行，不依赖用户登录

### 任务计划

- 名称：`CampusAutoLogin`
- 触发器：主触发器 `-Once` 立即开始 + 每 1 分钟重复（不传 `-RepetitionDuration`，XML 中无 `<Duration>` 节点即为无限重复），另加开机后延迟 30 秒的 `-AtStartup` 覆盖重启场景。**不能只用 `-AtStartup`**：它的重复要等开机事件发生后才计时，任务在开机后注册时本次开机内永不触发（实际踩过，表现为“下次运行时间”始终为空）。**也不能用 `-RepetitionDuration ([TimeSpan]::MaxValue)` 显式写无限**：PS 5.1 会序列化成 `P99999999DT23H59M59S`，Task Scheduler 判定越界，`Register-ScheduledTask` 直接失败并报 `0x80041318`（实际踩过，表现为任务根本没注册上，后续全是“找不到任务”）
- 主体：SYSTEM，最高权限
- 操作：隐藏窗口运行 PowerShell 脚本
- 电池供电时也运行（笔记本场景）
- 单次执行超时 5 分钟

## 为什么不需要路由器

1. GameViewer 是出站连接，NAT 后不需要公网 IP
2. Windows 账号无密码 + GameViewer LocalSystem 自启 = 开机即远程可达
3. 路由器方案有变砖风险和校规风险，收益有限
